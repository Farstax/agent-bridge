# Grok Build native-contract spike evidence

Issue: #416

Decision: **B — headless `streaming-json`**

This file restores the sanitized evidence record referenced by the completed #416 spike. It records only observations that were captured in the issue discussion; raw provider payload bodies were not committed and are not reconstructed here.

## Environment

- Grok Build: `1.0.5 (5115b46bc9)`
- Evaluated surfaces:
  - headless `grok -p <prompt> --output-format streaming-json`
  - ACP `grok agent ... stdio`

## Sanitized probe evidence

| Probe | Headless `streaming-json` | ACP |
| --- | --- | --- |
| Fresh authenticated prompt | PASS | PASS after `initialize` + `authenticate(methodId=cached_token)` |
| Native session continuation | PASS using returned session ID | PASS using session create/load semantics |
| Process restart / reload | One-shot process model; native resume PASS | PASS after process restart + `session/load` |
| Tool use followed by answer | PASS | PASS |
| Answer / reasoning separation | PASS: only `text.data` is answer content | PASS: only `agent_message_chunk` is answer content |
| Cancellation | PASS via SIGTERM; observed exit `143` | Exercised during spike |
| Missing authentication | Bounded failure observed | Explicit authentication required |
| Protocol noise | Typed lifecycle events remained separate from answer content | Non-fatal `AuthorizationRequired` worker message observed on stderr during successful prompts |

## Safety conclusions

For headless mode, only `text.data` is eligible for user-visible answer content. `thought`, tool, lifecycle, protocol, unknown, error, stderr, and credential data are not answer content. The terminal `end` event owns native session identity and terminal stop evidence.

For ACP, only `agent_message_chunk` was eligible for answer presentation. Thought, tool, protocol, permission, stderr, and authentication traffic remained separate.

## Decision rationale

Headless `streaming-json` was selected because it proved the required fresh/resumed session behavior, typed answer separation, tool separation, bounded cancellation, and authentication failure behavior while fitting Agent Bridge's existing supervised one-shot process ownership. ACP added long-lived protocol/authentication and stderr-classification complexity without a required capability advantage for this integration slice.

The implementation therefore remains provider-owned and narrow:

1. invoke Grok headless with `streaming-json`;
2. persist/resume Grok's native session ID;
3. surface only documented answer events;
4. fail closed on unknown or contradictory terminal protocol;
5. keep Grok out of production/default routing until isolated qualification passes.
